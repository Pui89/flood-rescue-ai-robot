# Free and Open-Source Tools, Funding, Compute and Hardware Support

This is the complete shared resource guide for PUI89 AI Robotics. It covers free software, funding leads, compute programs, hardware-support routes, contact guidance and the 2026–2028 plan.

**Important:** A program link is an opportunity to investigate, not proof of eligibility or an award. Grants, cloud credits, equipment loans, discounts and donations are not guaranteed. Before applying, check the official page for current status, country restrictions, deadlines, business/university requirements, eligible costs, terms and commercial-use conditions. We have not received confirmation of funding or hardware unless a separate written award/loan agreement says so.

## 1. Free and open-source software

These tools are free/open-source or have free tiers. “Free” does not mean every model, dataset, hosted service, hardware device or commercial use is free. Review each license and current usage limits.

### Robotics, simulation and motion
- **ROS 2** — robotics middleware, nodes, drivers and communication: https://docs.ros.org/
- **Gazebo** — robot, world, physics and sensor simulation: https://gazebosim.org/
- **Webots** — open-source robot simulator: https://cyberbotics.com/
- **Nav2** — ROS 2 navigation stack: https://nav2.org/
- **SLAM Toolbox** — mapping and localization: https://github.com/SteveMacenski/slam_toolbox
- **MoveIt 2** — robotic arm planning and manipulation: https://moveit.ros.org/
- **RViz** — ROS visualization (documented with ROS 2): https://docs.ros.org/
- **MuJoCo** — physics and control simulation: https://mujoco.org/
- **Blender** — 3D asset and scene creation: https://www.blender.org/
- **FreeCAD** — parametric CAD: https://www.freecad.org/

### AI, vision, 3D and inference
- **OpenCV** — image/video processing and computer vision: https://opencv.org/
- **PyTorch** — deep learning framework: https://pytorch.org/
- **Open3D** — point clouds, 3D geometry and registration: https://www.open3d.org/
- **ONNX Runtime** — cross-platform model inference: https://onnxruntime.ai/
- **OpenVINO** — model optimization/inference for supported hardware: https://docs.openvino.ai/
- **Hugging Face Hub** — models, datasets and demos; model and dataset licenses differ: https://huggingface.co/
- **Anomalib** — visual anomaly-detection research: https://github.com/open-edge-platform/anomalib

### Testing, data, deployment and collaboration
- **Git and GitHub** — version control and project collaboration: https://git-scm.com/ and https://github.com/
- **GitHub Actions** — CI/testing with plan-specific usage limits: https://docs.github.com/actions
- **pytest** — Python testing: https://docs.pytest.org/

- **Hugging Face Spaces** — host eligible demos within current free-tier limits: https://huggingface.co/spaces

Start with tools that run locally on the computer already available. Use simulation and small datasets first; do not assume cloud GPUs or physical robots are free.

## 6. Simulation-first workflow and reproducible evidence

1. Install only the tools needed for the current milestone; record OS, versions, hardware and setup steps.
2. Build the first prototype in simulation using Gazebo or Webots before buying hardware.
3. Create automated tests and record test commands, seeds, configurations and dependency versions.
4. Publish benchmark protocols with metrics, test conditions, raw result files, failure cases and known limitations.
5. Separate simulated, lab and real-world results. Never describe simulation-only performance as field-proven.
6. Prepare a short public demo and a one-page support request linked to evidence.
7. Apply to programs only after checking current eligibility, application windows and terms.
8. Track every funding/hardware request in a support ledger: program, URL, date, requested support, eligibility checked, status, restrictions and next action.
9. Keep software, model and dataset license records, including any commercial-use restrictions.
10. Before real deployment, conduct project-specific safety, privacy, legal and operational reviews.

## 7. 2026–2028 development and support plan

- **2026 — foundation:** simulation-first proof of concept on available computer; establish software tests, reproducible benchmark protocols, raw-result storage, risk documentation and public demonstrations. Apply only to relevant programs that are open and for which eligibility can be established.
- **2027 — validation and partnerships:** use measured evidence to approach universities, research labs, field-test partners and suppliers for scoped collaborations or hardware loans. Validate in controlled lab settings and publish failures as well as successes.
- **2028 — responsible commercialization:** consider larger grants, paid support, deployment partnerships and pilot customers only after reliability, safety, legal compliance, maintenance and real-world performance are demonstrated. Keep the open-source core and document optional paid services separately.

## Evidence and integrity rules

- Mark every result as a **target**, **simulation**, **lab test** or **field test**.
- Do not claim funding, a partnership, donated/loaned hardware, certification, or benchmark success until it is documented.
- Do not present credits as cash or physical hardware.
- Check software, model, dataset and hardware SDK licenses before redistributing or commercializing.
- Keep safety limitations, failure cases and human-review requirements visible.

Start with one depth/stereo camera or RGB camera, one compute board, a safe low-speed mobile base and basic environmental sensors. Ask suppliers for loan/demo units first. Mapping error, localization error, navigation completion rate, obstacle-detection precision/recall, mission completion time, communication-loss response and emergency-stop behavior. Publish conditions and raw results; do not claim field readiness from simulation alone.
