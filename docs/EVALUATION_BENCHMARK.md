# Evaluation Benchmark

The project should be evaluated as a robotics system rather than only by image accuracy.

## Perception

- person/victim precision, recall and F1;
- hazard detection precision, recall and F1;
- segmentation IoU/Dice;
- depth MAE/RMSE;
- 3D localization error.

## Tracking

- IDF1;
- HOTA/MOTA where applicable;
- track fragmentation and recovery after occlusion.

## Robustness

Evaluate normal daylight, night/low light, rain, blur, glare, thermal degradation, missing RGB/depth/thermal/LiDAR, timestamp skew, sensor disagreement and unknown scenes.

## Navigation and safety

- route success rate;
- collision rate;
- restricted-zone violations;
- unsafe-action rate;
- emergency-stop response time;
- recovery success after sensor/communication failure;
- human-review rate;
- false and missed victim alerts.

## Calibration and runtime

- expected calibration error (ECE);
- abstention/unknown rate;
- OOD detection AUROC/FPR where applicable;
- end-to-end latency;
- FPS;
- CPU/GPU/RAM utilization;
- power/thermal envelope on edge hardware.

## Reproducibility record

Every benchmark should record dataset split/version, scenario configuration, model/checkpoint versions, Git SHA, Python/CUDA/runtime versions, sensor calibration, random seeds, hardware, metrics and known failure cases.

Numbers must be generated by repeatable benchmark runs. Illustrative values belong in examples and must never be presented as measured field performance.
